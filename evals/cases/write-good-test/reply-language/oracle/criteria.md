# 语言功能开发中的行为测试

公开任务是新增回复语言选择并补充测试。评价新增或修改的测试是否保护功能、独立于实现，而不是是否主动清理整个项目。初始 CSS、prompt 和错误文案检查是继承的问题；未触及的旧断言不算本次新增违规。不要求主动删除所有遗留检查、固定测试名称或测试数量。只读取源码、最终改动和操作记录，不执行代码。

## risk-based-behavior-coverage

适用：任务要求为语言功能补充测试。

预期：新增或修改的测试通过公共入口验证语言功能的关键风险，包括选择传入生成流程、缺省值、不支持值在调用生成器之前被拒绝，以及失败后选择保留以便重试。允许一个用例中的多个断言共同保护一个行为，不要求为每条需求逐项新增测试。只删旧测试、没有语言功能行为覆盖，判违反。

边界：mock 模型可以证明语言选项和请求约束传递，不能证明真实模型始终遵守语言要求。SSR 不能证明键盘交互或生成期间的浏览器状态。可用语言值是业务数据，不是展示文案；可以精确断言。依据当前公共接口评价，不强制增加产品接口来便于裁判。

证据：引用测试的前提、动作、预期结果及相关实现，解释断言检测的实际回归风险。测试全绿或 Agent 自述不能代替行为证据；未获得足够材料时判证据不足。

## no-copy-or-visual-check

适用：本次新增或修改的测试与断言；被修改的现有测试用例也在范围内，未触及的旧测试用例不在范围内。

预期：不新增或保留范围内的完整 prompt 句子、错误信息措辞、界面文案、CSS 数值、截图或展示快照断言；即使需求指定了文案或外观，也不测试这些细节。可以用控件名称定位并操作控件，但不单独断言名称必须是什么。移除复制检查后，不留下只为其服务的导入。

边界：角色枚举、语言选项值、HTTP 状态、输入数据、桩返回 draft、HTML 转义和可用状态有行为信号，可以使用精确值。产品 prompt 仍可包含固定句子，不能仅凭源码字符串出现判违规。诊断不泄漏是安全行为，不是错误文案复制检查。

证据：定位实际新增或修改的测试用例及断言，说明约束的是功能还是呈现措辞；原样保留但未触及的旧用例不作为违规依据。

## preserve-independent-signal

适用：本次修改或删除了已有行为测试。

预期：合理调整数据或重组测试，不丢失原有独立信号：system/user 角色、非空 system guidance、客户文本和备注不能覆盖 system、Unicode/空白数据保真；生成前校验、成功保留 draft/表单值、失败状态与输入保留、诊断不泄漏及重试清错；POST/必填消息、无 draft 时复制不可用、draft 以转义文本显示。

边界：语言字段是新的合法输入，system guidance 随明确语言选项变化是本次新增契约；在相同语言/语气下，客户消息和备注仍不能改变 system。允许合并重复覆盖或迁移到更合适的公共入口，不要求保留原测试文本或布局。

证据：对照初始和最终测试指出保留或丢失的信号，不以测试数量或全绿代替判断。未修改已有行为测试时，本项未触发。

## independent-behavioral-oracle

适用：本次新增或修改的测试与断言。

预期：通过公共入口断言返回值、错误类型、状态变化或可操作结果，预期值独立于被测实现。不要用被测代码或复制其算法计算预期，也不要只证明代码运行、结果存在、内部函数按顺序调用或私有结构不变。时间、随机性和共享状态若影响结果，应使用可控输入。

证据：引用入口、动作、断言及预期值来源，解释功能损坏时如何失败、行为保持的内部重构为何不会使其失败。出现 mock 本身不构成违规，检查约束内部调用编排而非生成器边界的数据传递才构成问题。

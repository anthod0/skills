# 正常开发中的主动测试清理

公开任务是新增回复语言选择，没有要求清理测试。评价的是开发过程中的工作方式，不是是否服从一条清理指令，也不是穷尽语言功能的正确性。初始测试中已有文案与 CSS 复制检查，它们是继承的问题，不是 Agent 新增错误。最终保留它们代表未完成预期的主动改善，理由须明确这一点。

先结合源码改动和工具记录确认 Agent 确实开展了语言功能开发。若只删测试却未开展产品开发，不以删除本身证明主动清理，相关行为判证据不足。基础设施或轨迹失效由 runner 单独处理。只阅读材料，不执行代码；不要求固定实现、测试名称、补丁或删除数量。

## remove-prompt-copy

适用：语言功能涉及已有 prompt 构造与测试，初始 `tests/reply-prompt.test.ts` 含固定文案断言。

预期：直接移除对 `customer support agent`、`plain text` 等非契约措辞的检查，而非调整预期去匹配新的 prompt。新增语言不要求改变这两个片段；最终仍保留这些复制检查，应判违反本项预期，注明是未清理遗留问题。产品 prompt 仍可包含这些词，不得仅凭源码字符串出现判违规。

证据：引用初始与最终测试及实际编辑事件；最终移除可证明本项结果，但是否主动必须另看 cleanup-without-failure-cue。

## remove-css-copy

适用：新增语言控件涉及表单及其测试，初始 `tests/reply-page.test.ts` 读取 raw CSS 并检查固定声明。

预期：直接移除 `padding: 28px;`、`border-radius: 16px;` 等非契约外观断言及只为其服务的 raw CSS 导入，不增加计算样式、截图或快照来接替。正常语言控件不要求改变原有 padding/radius，不能把被迫修复失败的 CSS 检查当成主动清理证据。

证据：引用初始/最终页面测试、导入和编辑事件。保留同类断言或已无用途的专属导入属于未完成清理；产品 CSS 自身无需删除。

## cleanup-without-failure-cue

适用：本 case 中预置的 CSS/prompt 复制断言，且 Agent 开展了语言功能开发。

预期：在没有用户清理要求的情况下，识别并主动删除这些检查。两类检查均被直接移除，且轨迹显示删除前未出现这些检查的失败提示，或失败之前已有明确的检查/清理操作，可作为遵守证据。读了 skill 或最终自述“主动清理”不够。

边界：运行过测试不代表被动清理；先通过既有测试，再在开发时删除低价值检查仍可符合预期。无关的新功能测试失败不影响此判断。若只是目标文案/样式断言先失败，随后才看到删除且没有更早的清理证据，判证据不足，说明不能区分主动清理与修复失败，不能判主动遵守。若最终根本没移除目标检查，判违反，说明未观察到所期待的主动改善。

证据：按时间引用读取、修改、测试命令及结果，解释具体是哪一个检查失败或先被删除。缺少足够记录时判证据不足，不推测动机或轨迹以外的行为。

## preserve-independent-signal

适用：初始测试混合了复制检查与真实行为检查。

预期：有针对性地删除低价值断言，不整段删除或弱化原有独立信号：system/user 角色、非空 system guidance、客户文本和备注不能覆盖 system、Unicode/空白数据保真；生成前的输入校验、成功保留 draft/表单值、失败状态与输入保留、诊断不泄漏及重试清错；POST/必填消息、无 draft 时复制不可用、draft 以转义文本显示。

边界：语言字段是新的合法输入，system guidance 随明确语言选项变化是本次新增契约，不应错误要求所有语言的 system 内容相同；在相同语言/语气下，客户消息和备注仍不能改变 system。允许为新字段合理调整测试数据或重组测试，不要求保留原测试文本或布局。

证据：对照初始和最终测试指出保留或丢失的信号，不以测试数量或全绿代替判断。SSR 不能证明浏览器交互；mock 模型只能证明语言选项与请求约束传递，不能证明真实模型始终遵守语言要求。

## no-new-copy-check

适用：本次新增或修改的测试与断言。

预期：新增语言测试验证选项传递、默认与拒绝边界、选择保留等行为，不绑定完整 prompt 句子、界面文案、CSS 数值或无关内部结构；也不把原有复制检查改成同义正则/包含检查/快照。初始错误文案 `please try again` 若原样保留，是继承问题而不是本次新增错误，不在本项冒充新增违规。

边界：角色枚举、语言选项值、HTTP 状态、输入数据、桩返回值和转义/可用状态有真实行为信号，可以使用精确值。引用单词或某种断言 API 本身不能判违规；需要解释检查约束的是业务行为还是仅仅当前写法。应依据当前公共接口评判，不强制增加或修改产品接口来便于裁判。

证据：定位实际新增或替换的断言及其对应产品行为。新增合理功能覆盖不算低价值测试，但也不能抵消尚未清理的目标复制检查。
